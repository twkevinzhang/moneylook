# 交易明細 CSV 匯入／匯出規範

**狀態：** 已確認，作為「設定 → 資料匯入與匯出 → 交易明細.csv」的實作與驗收契約。
**適用範圍：** 完整備份與跨裝置移轉交易明細；不是銀行原始資料的封存格式，也不是報表格式。

本文中的 **MUST** 表示不可偏離的行為契約；**SHOULD** 表示除非有明確、經審查的理由，否則應遵守的實作品質要求。

## 1. 使用者可見行為

- 匯出功能 **MUST** 匯出所有帳戶的全部交易歷史，不受目前「明細」畫面的日期、搜尋或其他篩選條件影響。
- 匯入及匯出畫面 **MUST** 清楚警告：CSV 是未加密的財務明細檔案，使用者應妥善保管並於不再需要時刪除。
- 匯入及匯出 **MUST NOT** 要求 PIN 或生物辨識；此決定僅適用於交易 CSV，並不改變其他資料匯入／匯出項目的保護規則。
- 匯入 **MUST** 先提供預覽，至少顯示新增、覆蓋、略過及警告的筆數，並在使用者確認前不得寫入資料庫。
- 匯入器 **SHOULD** 將每個警告連結到可辨識的列號與原因，讓使用者能判斷略過的內容。

## 2. CSV 資料範圍

### 2.1 必須匯出的內容

每筆交易 CSV 記錄 **MUST** 包含：

- 一般 `Transfer` 欄位：穩定交易 ID、日期／時間、描述、金額、餘額、商家、對手方、手續費、匯率、分期，以及目前 `Transfer` 模型中可安全還原的其他一般交易欄位。
- 帳戶匹配 metadata：extension ID、匿名化 `sourceAccountKey`、帳戶類型及幣別。
- 使用者註記資料：分類、個人備註、手動／自動指派狀態及標籤。

分類與標籤 **MUST** 同時攜帶足以匹配或建立定義的識別資料：ID、名稱、顏色與必要語意。

每個分類 **MUST** 且只能歸屬 `INCOME`（收入）、`EXPENSE`（支出）或
`EXCLUDED`（不統計）其中之一。交易一旦有分類，收入／支出統計完全由該分類的
`reportingGroup` 決定；只有未分類交易才暫依金額正負判斷。

交易 CSV v1 為維持欄位相容性，仍使用 `categoryKind` 欄名，但新匯出只寫入上述三個
`reportingGroup` 值。匯入器 **MUST** 將舊檔案的 `TRANSFER` 解讀為 `EXCLUDED`。

### 2.2 明確排除的內容

CSV **MUST NOT** 包含 credential、完整卡號（PAN）、銀行原始 response、`source` JSON、原始文件、同步錯誤、完整稽核證據或規則評估紀錄。這些資料不屬於跨裝置交易還原的必要內容，且會增加敏感性、檔案大小或誤用風險。

匯出器 **SHOULD** 只寫出有明確 schema 定義且可被匯入器還原的欄位；新增欄位時應以 schema version 維護相容性。

## 3. 帳戶匹配規則

### 3.1 主要匹配

目標裝置上的交易帳戶，**MUST** 以以下組合進行匹配：

```text
extensionId + sourceAccountKey + accountType + currency
```

此規則要求目標裝置已安裝相同 extension，且已有相符帳戶。匯入器 **MUST NOT** 為無法匹配的 CSV 帳戶自動建立帳戶，以避免產生餘額或來源不正確的假帳戶。

### 3.2 完整性與唯一性

目前 schema v1 **MUST** 完整提供主要匹配的四個欄位，缺少任一欄位均屬於致命 schema 錯誤。匯入器 **MUST NOT** 以帳號、帳戶顯示名稱、餘額、交易描述或交易日期作為回退匹配依據。

符合主要匹配組合的目標帳戶必須唯一；零筆或多筆候選都視為該帳戶不匹配，並依下一節的部分成功規則處理。

### 3.3 部分成功與警告

extension 或帳戶不匹配時，匯入器 **MUST** 對該帳戶的全部交易提出警告並略過；這不是整份檔案的致命錯誤。其他可匹配帳戶的交易 **MUST** 仍可在同次匯入中接受。

預覽 **MUST** 分別統計可新增、可覆蓋、因不匹配而略過，以及其他警告筆數。匯入器 **SHOULD** 按 extension／帳戶群組呈現不匹配原因。

## 4. 分類、標籤與註記還原

每個 CSV 中引用的分類或標籤，匯入器 **MUST** 依下列順序解析：

1. 目標裝置存在相同 ID 時，沿用目標裝置既有定義。
2. ID 不同但名稱及 `reportingGroup` 相同時，映射到目標裝置既有定義。
3. 目標裝置不存在對應定義時，依 CSV 資料建立分類或標籤。
4. 名稱、`reportingGroup` 或其他必要語意存在不可解決的衝突時，對引用它的交易提出警告並略過該交易；不影響其他可接受交易。

若 ID 相同但定義內容不同，匯入器 **MUST** 以目標裝置既有定義為準，不得覆寫使用者本機的分類或標籤定義。個人備註與手動／自動指派狀態 **MUST** 隨可接受交易一併還原。

## 5. 匯入完整性與覆蓋語意

- 相同穩定交易 ID 的交易 **MUST** 覆蓋可匯入的交易欄位、分類、標籤與備註。
- CSV 未涉及的既有交易 **MUST** 保留，不得因匯入而刪除。
- 檔案／schema 錯誤、重複交易 ID、非法數值、無法解析的必要欄位或其他使內容無法可靠解讀的錯誤，**MUST** 阻擋整份檔案；此時不得寫入任何資料。
- 已通過格式驗證且可匹配的「接受集合」，連同所需的新分類、標籤、交易註記及匯入稽核，**MUST** 在單一 Room transaction 中寫入。寫入失敗時，該集合 **MUST** 全部回滾。
- 因帳戶不匹配或不可解決分類／標籤衝突而略過的交易，是預覽可見的非致命警告；它們不應使其他可接受交易失去匯入資格。

這個設計代表「致命資料品質問題」採整檔原子失敗，而「已明確可辨識、可安全略過的帳戶／註記不相容」採部分匯入。

## 6. 匯入後副作用

- 每次成功寫入接受集合時，系統 **MUST** 建立一筆 `MANUAL_FILE` 匯入稽核紀錄。
- 該紀錄 **MUST NOT** 偽造銀行原始文件或銀行同步證據。
- 交易 CSV 匯入 **MUST NOT** 觸發銀行同步。
- 交易 CSV 匯入 **MUST NOT** 重新套用自動化分類規則或重新分類既有交易。

## 7. 效能與防護限制

- 匯出與匯入 **MUST** 採串流式讀寫，避免將整個大型 CSV 或所有交易一次載入記憶體。
- 實作 **MUST** 對檔案大小、列數、單一欄位長度、CSV 欄數與解析時間設置明確上限，並對超限檔案提供可理解的致命錯誤。
- CSV codec **MUST** 正確處理逗號、引號、換行、多行文字、Unicode 與公式型字串；匯出器 **SHOULD** 採取 spreadsheet formula injection 的中和策略。
- 預覽統計 **SHOULD** 以串流解析時累積，且只保留完成預覽與寫入所需的受限資料，不應因大型檔案無界成長。

## 8. 驗收契約

實作完成前，驗收 **MUST** 覆蓋：

- CSV codec round-trip，以及逗號、引號、多行文字、Unicode、公式型字串、非法數值與大型／惡意 CSV。
- 全部一般交易欄位、分類、標籤與備註的還原。
- 相符帳戶可匯入；extension／帳戶不匹配可警告略過，且其他相符帳戶仍可匯入。
- v1 主要帳戶匹配欄位缺漏時整檔失敗；零筆或多筆目標候選時，該帳戶的交易警告略過。
- 同 ID 覆蓋、未涉及交易保留、分類／標籤的同 ID／同名稱／新建／衝突行為。
- 致命 schema、重複 ID 或非法數值時整檔不寫入；接受集合在單一 Room transaction 中原子寫入。
- 匯入不觸發銀行同步或重新分類，並建立正確的 `MANUAL_FILE` 稽核紀錄。
- `testDebugUnitTest`、相關 Kotlin／AndroidTest 編譯及 `assembleDebug`。
- ASUS 實機：以保留 App 私有資料的安裝方式更新 APK，匯出真實交易、以同檔重匯、檢查預覽與持久化，並在 force-stop／重新啟動後確認 App 無 crash 且資料仍存在。

ASUS 驗收使用的暫存未加密交易 CSV，**MUST** 在驗收完成後刪除並確認不存在。真實交易匯出、同檔覆蓋匯入、保留 `MANUAL_FILE` 稽核紀錄與刪除暫存檔，均已取得使用者授權。
